What a T1204 XML file is

A T1204 XML file is one <Submission> with two parts:

  • T619 transmitter record. The wrapper that says who is sending the file: the transmitter's business number, a Submission Reference ID, a contact name, phone and email, and the language.
  • T1204 return. One <T1204Slip> per recipient, followed by one <T1204Summary> with the paying department's details and the totals for every slip in the file.

You upload the file to IFT, which checks it against CRA's XML schema. Electronic filing is required once you file more than 5 slips of a type in a calendar year. Below that, it is optional but still accepted.

CRA XML specifications in plain terms

TaxXML follows schema 1-26-3: T619 2026 for the transmitter record and T1204 2026V3 for the return. The elements you will see most:

  • payr_bn: on each slip, the paying department's 15-character business number. The summary carries it as bn.
  • RCPNT_BUS_NM: the recipient's business name.
  • sin, rcpnt_bn: the recipient's social insurance number or business number. Both tags appear on every slip; the one that doesn't apply gets a zero placeholder, such as 000000000 for the SIN.
  • rcpnt_tcd: recipient type, such as individual, corporation or partnership.
  • T1204_AMT: the amount paid, as srvc_pay_amt for service-only payments or mxd_gd_pay_amt for mixed goods and services.
  • tx_yr, slp_cnt: on the summary, the tax year and the number of slips, with the totals for each kind of payment.
  • rpt_tcd: report type. O for original, A for amendment, C for cancel.

The full rules are on CRA's site: XML specifications for information returns and the T619 2026 specification.

Common reasons CRA rejects a T1204 XML file

  • IDs that lost their leading zero. Excel treats a SIN like 046454286 as a number and drops the zero. Format the SIN and BN column as Text. TaxXML reads them as text, and flags any SIN that isn't 9 digits or fails the checksum.
  • Empty optional tags. Since CRA's October 2025 validation change, a tag with nothing in it, like <pstl_cd/>, gets the file rejected. Optional fields with no value must be left out entirely. TaxXML leaves out blank optional fields. Don't type "N/A" or a space to fill a cell.
  • Business number in the wrong format. A BN here is 15 characters: 9 digits, 2 letters, 4 digits. A 9-digit BN on its own is not enough.
  • Reused Submission Reference ID. Every file needs a new one. TaxXML bumps it for you (A to B) when you come back to resubmit.
  • A second original instead of an amendment. Corrections to accepted slips go in as an amendment, not another original.

T1204 XML questions

When is the T1204 return due?

On or before the last day of March following the calendar year in which the payments were made.

Do I have to file T1204 slips electronically?

Yes, if you file more than 5 T1204 slips for a calendar year. CRA requires electronic filing above that number. Internet File Transfer with an XML file is one of the accepted ways.

Which CRA XML schema does TaxXML use for T1204?

CRA XML schema 1-26-3: T619 2026 and T1204 2026V3. That includes the October 2025 validation change that rejects empty optional tags.

Is my data uploaded anywhere?

No. The spreadsheet is read and the XML is built in your browser. TaxXML does not send the file to a server or to CRA. You upload it to Internet File Transfer yourself. See Privacy.

How do I fix a T1204 that CRA already accepted?

File an amendment: set Report Type to Amendment (A) and include only the slips that changed, each one complete. Use a new Submission Reference ID. Do not send a second original.
