What a T5018 XML file is

A T5018 XML file is one <Submission> with two parts:

  • T619 transmitter record. The wrapper that says who is sending the file: the transmitter's CRA account number (usually the 15-character business number), a Submission Reference ID, a contact name, phone and email, and the language.
  • T5018 return. One <T5018Slip> per subcontractor, followed by one <T5018Summary> with the payer's details, the end date of the reporting period and the total paid to subcontractors.

You upload the file to IFT, which checks it against CRA's XML schema. Electronic filing is required once you file more than 5 slips of a type in a calendar year. Below that, it is optional but still accepted.

CRA XML specifications in plain terms

TaxXML follows schema 1-26-3: T619 2026 for the transmitter record and T5018 2026V3 for the return. The elements you will see most:

  • bn: the payer's 15-character account number on the RZ program, for example 123456789RZ0001, on every slip and the summary.
  • RCPNT_NM or CORP_PTNRP_NM: the subcontractor's name. Individuals use RCPNT_NM; corporations and partnerships use CORP_PTNRP_NM.
  • sin, rcpnt_bn: the subcontractor's social insurance number or business number (Box 24). Both tags appear on every slip; the one that doesn't apply gets a zero placeholder, such as 000000000 for the SIN.
  • rcpnt_tcd: recipient type, such as individual or corporation.
  • sbctrcr_amt: the construction subcontract payments for the period (Box 22).
  • PRD_END_DT: on the summary, the day, month and year your reporting period ends.
  • slp_cnt, tot_sbctrcr_amt: on the summary, the number of slips and the total paid.
  • rpt_tcd: report type. O for original, A for amendment, C for cancel.

The full rules are on CRA's site: XML specifications for information returns and the T619 2026 specification.

Common reasons CRA rejects a T5018 XML file

  • IDs that lost their leading zero. Excel treats a SIN like 046454286 as a number and drops the zero. Format the SIN and BN column as Text. TaxXML reads them as text, and flags any SIN that isn't 9 digits or fails the checksum.
  • Empty optional tags. CRA rejects files that contain empty optional tags: a tag with nothing in it, like <pstl_cd/>, gets the file rejected. Optional fields with no value must be left out entirely. TaxXML leaves out blank optional fields. Don't type "N/A" or a space to fill a cell.
  • Business number in the wrong format. A BN here is 15 characters: 9 digits, 2 letters, 4 digits. For the payer, T5018 uses the RZ program account, for example 123456789RZ0001, not the RP payroll account. A 9-digit BN on its own is not enough.
  • Reused Submission Reference ID. Every file needs a new one. TaxXML bumps it for you (A to B) when you come back to resubmit.
  • A second original instead of an amendment. Corrections to accepted slips go in as an amendment, not another original.

T5018 XML questions

When is the T5018 return due?

Within 6 months after the end of your reporting period. You can report on a calendar-year basis or on your fiscal period, and the deadline counts from the end of the period you chose.

Do I have to file T5018 slips electronically?

Yes, if you file more than 5 T5018 slips for a calendar year. CRA requires electronic filing above that number. Internet File Transfer with an XML file is one of the accepted ways.

Which CRA XML schema does TaxXML use for T5018?

CRA XML schema 1-26-3: T619 2026 and T5018 2026V3. It also follows CRA's rule that empty optional tags must be left out, because IFT rejects them.

Is my data uploaded anywhere?

No. The spreadsheet is read and the XML is built in your browser. TaxXML does not send the file to a server or to CRA. You upload it to Internet File Transfer yourself. See Privacy.

How do I fix a T5018 that CRA already accepted?

File an amendment: set Report Type to Amendment (A) and include only the slips that changed, each one complete. Use a new Submission Reference ID. Do not send a second original.
